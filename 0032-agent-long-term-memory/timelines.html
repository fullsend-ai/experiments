Seven issues, with and without memory

Seven fullsend bug reports were each copied into two test repositories that were alike except for a shared memory for the agents. Each row below is one copy's pipeline of agent runs, from the issue to the review agent's last verdict. With the revised memory instructions (the last five issues) the copy with memory got there sooner every time; with the first instructions (the first two) it was slower both times.

Where most of the saving came from

The review agent's main agent hands each sub-agent a brief. In all 10 reviews with memory under the revised instructions it wrote each brief to a file and sent a short pointer, as an earlier review had saved in memory; in 1 of the other 17 reviews it did. Median output of the main agent: 14,694 tokens against 50,248.

The purple columns in each issue's figure show it, one per review. More in the report

What the rows do not count

Retro runs, the wait for a maintainer to merge or close, a fix run a maintainer cancelled on #9320, and review starts cancelled within seconds are drawn in the issue figures but are not in the totals.

What this page does not show

Where the times come from. Bars are GitHub Actions agent jobs, from the job's start to its end. Issues, pull requests, verdicts and merges are GitHub's own times. Memory calls and known problems come from each run's transcript; all 608 of them fall inside their run's job.

Each copy is timed from its own issue. On #9572 the copy without memory was opened 2 h 10 min after the copy with memory; from #9320 on, both copies were opened within two seconds of each other.

Cost is fullsend's own estimate for each run, not a bill. The figures from each run's OpenTelemetry trace come from a tracing server that is not public; they are in data/.

Not shown: what each change contained and what each review found. Those are in the pull requests and in RESULTS.md.

Job logs and run artifacts on GitHub expire after 90 days (February 2027). The job links then still open the job, without its log.
